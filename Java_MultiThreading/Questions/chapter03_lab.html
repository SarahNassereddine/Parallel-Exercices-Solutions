Exercise 1: Parallel Array Sum

Problem: Calculate the sum of a large array of integers using multiple threads.

Sequential Code (Provided):

public class ArraySumSequential {
    public static void main(String[] args) {
        int size = 1000000;
        int[] array = new int[size];
        
        // Initialize array with values
        for (int i = 0; i < size; i++) {
            array[i] = i + 1;
        }
        
        // Sequential sum
        long startTime = System.nanoTime();
        long sum = 0;
        for (int i = 0; i < size; i++) {
            sum += array[i];
        }
        long endTime = System.nanoTime();
        
        System.out.println("Sum: " + sum);
        System.out.println("Time: " + (endTime - startTime) / 1_000_000 + " ms");
    }
}

Your Task:

  1. Create a parallel version using ExecutorService with a fixed thread pool
  2. Divide the array into chunks (one per thread)
  3. Each thread should calculate the sum of its chunk
  4. Combine the partial sums to get the final result
  5. Collect results using a thread-safe shared structure (e.g., synchronized list or AtomicLong for partial sums)
  6. Measure and compare execution time with the sequential version
💡 Multiple Approaches:
  • Option 1: Use ExecutorService with execute(Runnable) and a thread-safe result collection (recommended)
  • Option 2: Use Thread class with manual thread management
  • Option 3: Use Runnable interface with lambda expressions

Try implementing at least two different approaches to understand the trade-offs!

Hints:
  • Use Executors.newFixedThreadPool(numThreads) to create a thread pool
  • Calculate chunk size: chunkSize = array.length / numThreads
  • Each thread processes indices from startIndex to endIndex
  • Use execute(Runnable) to submit tasks; each task adds its partial sum to a shared thread-safe variable (e.g., AtomicLong) or collect in a synchronized list
Expected Output: The parallel version should produce the same sum but potentially faster execution time (depending on your CPU cores).

Exercise 2: Parallel Matrix Multiplication

Problem: Multiply two matrices using multiple threads, where each thread computes a portion of the result matrix.

Sequential Code (Provided):

public class MatrixMultiplicationSequential {
    public static void main(String[] args) {
        int size = 1000;
        int[][] matrixA = new int[size][size];
        int[][] matrixB = new int[size][size];
        int[][] result = new int[size][size];
        
        // Initialize matrices
        for (int i = 0; i < size; i++) {
            for (int j = 0; j < size; j++) {
                matrixA[i][j] = i + j;
                matrixB[i][j] = i * j;
            }
        }
        
        // Sequential matrix multiplication
        long startTime = System.nanoTime();
        for (int i = 0; i < size; i++) {
            for (int j = 0; j < size; j++) {
                result[i][j] = 0;
                for (int k = 0; k < size; k++) {
                    result[i][j] += matrixA[i][k] * matrixB[k][j];
                }
            }
        }
        long endTime = System.nanoTime();
        
        System.out.println("Time: " + (endTime - startTime) / 1_000_000 + " ms");
    }
}

Your Task:

  1. Create a parallel version where each thread computes a set of rows of the result matrix
  2. Use ExecutorService to manage threads
  3. Divide rows among threads (e.g., thread 0 computes rows 0-249, thread 1 computes rows 250-499, etc.)
  4. Ensure no race conditions (each thread writes to different rows)
  5. Measure performance improvement
💡 Multiple Approaches:
  • Option 1: Use ExecutorService (recommended for better resource management)
  • Option 2: Use Thread class with manual thread management
  • Division Strategy: Row-based (each thread computes several rows) or Block-based (each thread computes a rectangular block)

Try both row-based and block-based division to see which performs better!

Hints:
  • Each thread should be responsible for a range of rows: startRow to endRow
  • No synchronization needed if each thread writes to different rows
  • Use Runtime.getRuntime().availableProcessors() to determine optimal thread count

Exercise 3: Thread-Safe Counter with Synchronization

Problem: Multiple threads increment a shared counter. Implement proper synchronization to ensure correctness.

Sequential Code (Provided - This is actually a broken concurrent version):

public class CounterSequential {
    private static int counter = 0;
    private static final int NUM_THREADS = 10;
    private static final int INCREMENTS_PER_THREAD = 1000;
    
    public static void main(String[] args) throws InterruptedException {
        Thread[] threads = new Thread[NUM_THREADS];
        
        // Create threads
        for (int i = 0; i < NUM_THREADS; i++) {
            threads[i] = new Thread(() -> {
                for (int j = 0; j < INCREMENTS_PER_THREAD; j++) {
                    counter++; // NOT THREAD-SAFE!
                }
            });
            threads[i].start();
        }
        
        // Wait for all threads
        for (Thread t : threads) {
            t.join();
        }
        
        System.out.println("Expected: " + (NUM_THREADS * INCREMENTS_PER_THREAD));
        System.out.println("Actual: " + counter);
    }
}

Your Task:

  1. Fix the race condition using synchronized keyword
  2. Create an alternative version using ReentrantLock
  3. Create another version using AtomicInteger
  4. Compare the performance of all three approaches
  5. Verify that all versions produce the correct result
💡 Multiple Approaches:

This exercise is designed to explore multiple synchronization mechanisms:

  • Option 1: synchronized keyword (simplest, built-in)
  • Option 2: ReentrantLock (more flexible, explicit control)
  • Option 3: AtomicInteger (lock-free, often fastest for simple operations)

Implement all three versions and compare their performance and code complexity!

Hints:
  • Use synchronized method or block to protect the increment operation
  • For ReentrantLock, use lock() before increment and unlock() in finally block
  • AtomicInteger provides atomic operations like incrementAndGet()
  • Measure execution time for each approach

Exercise 4: Parallel Search in Array

Problem: Search for a value in a large array using multiple threads. Return the index if found, or -1 if not found.

Sequential Code (Provided):

public class SearchSequential {
    public static int search(int[] array, int target) {
        for (int i = 0; i < array.length; i++) {
            if (array[i] == target) {
                return i;
            }
        }
        return -1;
    }
    
    public static void main(String[] args) {
        int size = 10000000;
        int[] array = new int[size];
        for (int i = 0; i < size; i++) {
            array[i] = i;
        }
        
        int target = 5000000;
        long startTime = System.nanoTime();
        int result = search(array, target);
        long endTime = System.nanoTime();
        
        System.out.println("Found at index: " + result);
        System.out.println("Time: " + (endTime - startTime) / 1_000_000 + " ms");
    }
}

Your Task:

  1. Create a parallel version where each thread searches a portion of the array
  2. If any thread finds the target, all threads should stop (use a shared flag)
  3. Return the correct index (accounting for the chunk offset)
  4. Handle the case where the value is not found
  5. Use volatile or AtomicBoolean for the stop flag
💡 Multiple Approaches:
  • Stop Flag: Use volatile boolean or AtomicBoolean (both work, AtomicBoolean is more explicit)
  • Thread Management: Use ExecutorService (recommended) or manual Thread class
  • Result Collection: Use a thread-safe shared variable (e.g., AtomicInteger for index, volatile/AtomicBoolean for found flag) or synchronized block to store the result

Try different combinations to understand when to use each approach!

Hints:
  • Use volatile boolean found or AtomicBoolean to signal when target is found
  • Each thread should check the flag in its loop and exit early if found
  • When a thread finds the target, set the flag and return the index (with offset)
  • Use ExecutorService.execute(Runnable) with a shared result variable (e.g., volatile or AtomicInteger for the found index) protected by synchronization if needed

Exercise 5: Thread Coordination with ReentrantLock and Condition

Problem: Implement a task scheduler where multiple worker threads wait for tasks to be available, and a coordinator thread assigns tasks. Use ReentrantLock and Condition variables for proper thread coordination.

Sequential Code (Provided - This is a broken concurrent version):

import java.util.concurrent.locks.*;
import java.util.*;

public class TaskSchedulerSequential {
    private static Queue<String> tasks = new LinkedList<>();
    private static final int NUM_WORKERS = 3;
    private static final int NUM_TASKS = 10;
    
    public static void main(String[] args) throws InterruptedException {
        // Coordinator thread adds tasks
        Thread coordinator = new Thread(() -> {
            for (int i = 0; i < NUM_TASKS; i++) {
                tasks.offer("Task-" + i);
                System.out.println("Coordinator: Added Task-" + i);
                try { Thread.sleep(100); } catch (InterruptedException e) {}
            }
        });
        
        // Worker threads process tasks
        Thread[] workers = new Thread[NUM_WORKERS];
        for (int i = 0; i < NUM_WORKERS; i++) {
            final int workerId = i;
            workers[i] = new Thread(() -> {
                while (true) {
                    if (!tasks.isEmpty()) { // RACE CONDITION!
                        String task = tasks.poll();
                        if (task != null) {
                            System.out.println("Worker " + workerId + ": Processing " + task);
                            try { Thread.sleep(200); } catch (InterruptedException e) {}
                        }
                    }
                }
            });
        }
        
        coordinator.start();
        for (Thread worker : workers) {
            worker.start();
        }
        
        coordinator.join();
        Thread.sleep(2000); // Give workers time to finish
    }
}

Your Task:

  1. Fix the race condition using ReentrantLock to protect the shared task queue
  2. Use Condition variables so worker threads wait when no tasks are available
  3. Use Condition.signalAll() when the coordinator adds a new task
  4. Implement proper shutdown: coordinator signals workers when all tasks are done
  5. Use a while loop (not if) to check the condition, handling spurious wakeups
  6. Ensure workers terminate gracefully when all tasks are completed
💡 Multiple Approaches:
  • Option 1: Use ReentrantLock with Condition variables (recommended for this exercise)
  • Option 2: Use BlockingQueue (simpler, but less control over waiting behavior)

Try implementing with BlockingQueue as well to see how it simplifies the code, but understand that ReentrantLock+Condition gives you more control!

Hints:
  • Create a ReentrantLock and get a Condition from it: lock.newCondition()
  • Workers should: lock.lock() → check condition in while loop → condition.await() if no tasks → process task → lock.unlock()
  • Coordinator should: lock.lock() → add task → condition.signalAll() → lock.unlock()
  • Use a boolean flag (e.g., allTasksDone) to signal when coordinator finishes
  • Always use try-finally to ensure lock.unlock() is called
  • Remember: await() must be called while holding the lock, and it releases the lock automatically
Expected Output: All tasks should be processed exactly once by worker threads, with no race conditions. Workers should wait efficiently when no tasks are available, and terminate properly when all tasks are done.

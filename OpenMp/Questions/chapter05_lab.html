Exercise 1: Parallel Array Processing

Problem: Process a large array in parallel using OpenMP's parallel for directive.

Sequential Code (Provided):

#include <stdio.h>
#include <stdlib.h>
#include <time.h>

#define SIZE 10000000

int main() {
    double *array = (double*)malloc(SIZE * sizeof(double));
    
    // Initialize array
    for (int i = 0; i < SIZE; i++) {
        array[i] = i;
    }
    
    clock_t start = clock();
    
    // Process array
    for (int i = 0; i < SIZE; i++) {
        array[i] = array[i] * array[i] + 1.0;
    }
    
    clock_t end = clock();
    double time_taken = ((double)(end - start)) / CLOCKS_PER_SEC;
    printf("Time taken: %f seconds\n", time_taken);
    
    free(array);
    return 0;
}

Your Task:

  1. Add #include <omp.h> header
  2. Add #pragma omp parallel for before the processing loop
  3. Compile with OpenMP: gcc -fopenmp program.c -o program
  4. Set number of threads using omp_set_num_threads() or environment variable OMP_NUM_THREADS
  5. Measure and compare execution time
Hints:
  • Basic parallel for: #pragma omp parallel for
  • Set threads: omp_set_num_threads(4); or export OMP_NUM_THREADS=4
  • Print thread info: printf("Thread %d processing\n", omp_get_thread_num());
  • Compile: gcc -fopenmp -O2 program.c -o program

Exercise 2: Parallel Sum with Reduction

Problem: Calculate the sum of a large array using OpenMP reduction clause.

Sequential Code (Provided):

#include <stdio.h>
#include <stdlib.h>

#define SIZE 10000000

int main() {
    double *array = (double*)malloc(SIZE * sizeof(double));
    
    // Initialize array
    for (int i = 0; i < SIZE; i++) {
        array[i] = 1.0;
    }
    
    double sum = 0.0;
    for (int i = 0; i < SIZE; i++) {
        sum += array[i];
    }
    
    printf("Sum: %f\n", sum);
    free(array);
    return 0;
}

Your Task:

  1. Use #pragma omp parallel for reduction(+:sum) to parallelize the sum
  2. Try different reduction operations: +, *, max, min
  3. Compare with a version using critical section (slower approach)
  4. Measure performance difference
💡 Multiple Approaches:
  • Option 1: Use reduction clause (recommended, fastest)
  • Option 2: Use critical section (slower, more contention)
  • Option 3: Use local variables and combine at end (manual reduction)

Implement all three approaches and measure performance - reduction is significantly faster!

Hints:
  • Reduction syntax: #pragma omp parallel for reduction(operation:variable)
  • Operations: +, -, *, /, max, min, &, |, ^, &&, ||
  • Reduction is much faster than using critical sections
  • Each thread gets a private copy, combined at the end

Exercise 3: Parallel Dot Product

Problem: Calculate the dot product of two vectors using OpenMP with proper data sharing.

Sequential Code (Provided):

#include <stdio.h>
#include <stdlib.h>

#define SIZE 10000000

int main() {
    double *a = (double*)malloc(SIZE * sizeof(double));
    double *b = (double*)malloc(SIZE * sizeof(double));
    
    // Initialize vectors
    for (int i = 0; i < SIZE; i++) {
        a[i] = 1.0;
        b[i] = 2.0;
    }
    
    double dot_product = 0.0;
    for (int i = 0; i < SIZE; i++) {
        dot_product += a[i] * b[i];
    }
    
    printf("Dot product: %f\n", dot_product);
    
    free(a);
    free(b);
    return 0;
}

Your Task:

  1. Parallelize the dot product loop using #pragma omp parallel for reduction(+:dot_product)
  2. Ensure arrays a and b are shared (default)
  3. Use reduction for dot_product
  4. Measure performance improvement
  5. Try different schedule clauses: static, dynamic, guided
💡 Multiple Approaches:

Try different scheduling strategies:

  • static: Equal chunks assigned at compile time (good for uniform work)
  • dynamic: Chunks assigned at runtime (good for varying work per iteration)
  • guided: Decreasing chunk sizes (good for load balancing)
  • auto: Let OpenMP decide

Test different schedule types: schedule(static), schedule(dynamic, chunk_size), schedule(guided) and compare performance!

Hints:
  • Arrays are shared by default
  • Use reduction for the accumulator variable
  • Schedule examples:
    • schedule(static) - equal chunks
    • schedule(dynamic, 1000) - dynamic with chunk size 1000
    • schedule(guided) - decreasing chunk sizes

Exercise 4: Parallel Matrix Multiplication

Problem: Multiply two matrices using OpenMP, parallelizing the outer loop.

Sequential Code (Provided):

#include <stdio.h>
#include <stdlib.h>
#include <time.h>

#define SIZE 1000

int main() {
    double **A = (double**)malloc(SIZE * sizeof(double*));
    double **B = (double**)malloc(SIZE * sizeof(double*));
    double **C = (double**)malloc(SIZE * sizeof(double*));
    
    for (int i = 0; i < SIZE; i++) {
        A[i] = (double*)malloc(SIZE * sizeof(double));
        B[i] = (double*)malloc(SIZE * sizeof(double));
        C[i] = (double*)malloc(SIZE * sizeof(double));
    }
    
    // Initialize matrices
    for (int i = 0; i < SIZE; i++) {
        for (int j = 0; j < SIZE; j++) {
            A[i][j] = i + j;
            B[i][j] = i * j;
        }
    }
    
    clock_t start = clock();
    
    // Matrix multiplication
    for (int i = 0; i < SIZE; i++) {
        for (int j = 0; j < SIZE; j++) {
            C[i][j] = 0.0;
            for (int k = 0; k < SIZE; k++) {
                C[i][j] += A[i][k] * B[k][j];
            }
        }
    }
    
    clock_t end = clock();
    double time_taken = ((double)(end - start)) / CLOCKS_PER_SEC;
    printf("Time taken: %f seconds\n", time_taken);
    
    // Free memory
    for (int i = 0; i < SIZE; i++) {
        free(A[i]);
        free(B[i]);
        free(C[i]);
    }
    free(A);
    free(B);
    free(C);
    
    return 0;
}

Your Task:

  1. Parallelize the outer loop (i loop) using #pragma omp parallel for
  2. Make loop variable i private
  3. Ensure j and k are private (they should be by default in the loop)
  4. Try parallelizing with collapse(2) for both outer loops
  5. Compare performance of different approaches
💡 Multiple Approaches:
  • Option 1: Parallelize only outer loop (i) - good for row-based parallelism
  • Option 2: Use collapse(2) to parallelize both i and j loops - more parallelism
  • Option 3: Try different schedule types with collapse for load balancing

Test both approaches and see which gives better performance on your system!

Hints:
  • Parallelize outer loop: #pragma omp parallel for private(i, j, k)
  • Or use collapse: #pragma omp parallel for collapse(2) for i and j loops
  • Variables declared in loop are private by default
  • Matrices A, B, C are shared (read-only for A, B; write-only per row for C)

Exercise 5: Parallel Counter with Critical Section

Problem: Count occurrences of a condition in an array using OpenMP, comparing critical section vs atomic vs reduction.

Sequential Code (Provided):

#include <stdio.h>
#include <stdlib.h>

#define SIZE 10000000

int main() {
    int *array = (int*)malloc(SIZE * sizeof(int));
    
    // Initialize array
    for (int i = 0; i < SIZE; i++) {
        array[i] = i % 100;
    }
    
    int count = 0;
    for (int i = 0; i < SIZE; i++) {
        if (array[i] > 50) {
            count++;
        }
    }
    
    printf("Count: %d\n", count);
    free(array);
    return 0;
}

Your Task:

  1. Create version 1: Use #pragma omp critical to protect the counter increment
  2. Create version 2: Use #pragma omp atomic for the increment
  3. Create version 3: Use reduction(+:count) (best approach)
  4. Compare performance of all three versions
  5. Explain why reduction is fastest
💡 Multiple Approaches:

This exercise is designed to compare different synchronization mechanisms:

  • Version 1: critical section (most overhead, serializes all increments)
  • Version 2: atomic operation (faster than critical, hardware-supported)
  • Version 3: reduction (fastest, no contention, each thread has private copy)

Implement all three versions and measure performance - reduction should be significantly faster!

Hints:
  • Critical section: #pragma omp critical { count++; }
  • Atomic: #pragma omp atomic before count++
  • Reduction: #pragma omp parallel for reduction(+:count)
  • Reduction is fastest because each thread has a private copy
  • Atomic is faster than critical but slower than reduction

Exercise 6: Parallel Sections

Problem: Execute different independent tasks in parallel using OpenMP sections.

Sequential Code (Provided):

#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

void task1() {
    printf("Task 1: Processing data...\n");
    sleep(2);
    printf("Task 1: Done\n");
}

void task2() {
    printf("Task 2: Reading file...\n");
    sleep(2);
    printf("Task 2: Done\n");
}

void task3() {
    printf("Task 3: Computing...\n");
    sleep(2);
    printf("Task 3: Done\n");
}

int main() {
    task1();
    task2();
    task3();
    return 0;
}

Your Task:

  1. Use #pragma omp parallel sections to run tasks in parallel
  2. Mark each task with #pragma omp section
  3. Measure total execution time (should be ~2 seconds instead of 6)
  4. Add a fourth task and observe behavior
Hints:
  • Structure: 
    #pragma omp parallel sections
{
    #pragma omp section
    task1();
    
    #pragma omp section
    task2();
    
    #pragma omp section
    task3();
}
  • Each section runs in a different thread
  • All sections complete before continuing

Compilation Instructions

All OpenMP programs must be compiled with the -fopenmp flag:

gcc -fopenmp program.c -o program

Or with optimization:

gcc -fopenmp -O2 program.c -o program

Set number of threads at runtime:

export OMP_NUM_THREADS=4
./program

Exercise: The Producer-Consumer Problem

Objective

The goal of this exercise is to master thread synchronization using Mutexes and Condition Variables. You will implement various scenarios of the classic Producer-Consumer problem, learning how to manage shared resources (the buffer) while ensuring data integrity and preventing race conditions.

Cases to Implement

Develop a parallel solution for each of the following scenarios using the PThreads library:

Case 1: Single Producer & Single Consumer (Variable Load)

Implement a system with exactly one producer and one consumer. The producer fills one or more elements in the buffer, and then the consumer reads one or more elements. The threads should coordinate so the consumer never reads from an empty buffer and the producer never writes to a full one.

Case 2: Single Producer & Single Consumer (Full Cycle)

One producer and one consumer. In this restricted mode, the producer must fill all elements of the buffer before the consumer is allowed to start. The consumer must then read all elements before the producer can start reproducing data.

Case 3: Single Producer & Single Consumer (Chunk-based)

One producer and one consumer. The producer fills the buffer in specific chunks (blocks of data). Once a chunk is ready, the consumer can read one or more chunks. This explores synchronization at a higher granularity than individual elements.

Case 4: Multi-Producer & Multi-Consumer (Bulk Operations)

A system with many producers and many consumers. The synchronization rule is strict: the aggregate of all producers must fully produce the entire buffer before any consumer can act. Similarly, all consumers must fully empty the buffer before producers can start again.

Case 5: Multi-Producer & Multi-Consumer (Chunk-based Bulk Operations)

A system with many producers and many consumers, similar to Case 4, but with chunk-based synchronization. The aggregate of all producers must fully produce the entire buffer in chunks (blocks of data) before any consumer can act. Similarly, all consumers must fully empty the buffer by reading complete chunks before producers can start again. This combines the bulk operation model of Case 4 with the chunk granularity of Case 3.

Case 6: Multi-Producer & Multi-Consumer (Fairness)

Multiple producers and many consumers. Same as Case 5 (chunk-based bulk operations): the aggregate of all producers must fully produce the entire buffer in chunks before any consumer can act, and all consumers must fully consume the buffer before producers can start again. Additionally, a thread-level fairness constraint is enforced: No single thread (neither producer nor consumer) is allowed to process two chunks consecutively. This forces work rotation between the available threads.

Case 7: Multi-Producer & Multi-Consumer (Strict Rotation)

Many producers and many consumers. Same aggregate progress as Case 5: the buffer must be fully produced in chunks before any consumption begins, and fully consumed in chunks before production starts again. In this most restrictive case, a strict rotation is enforced: each individual producer is allowed to fill exactly and only one chunk during a single production round. Likewise, each consumer reads exactly and only one chunk per consumption round.

Note: For this case, the Buffer_Limit should be exactly equal to CHUNK_SIZE * number of Producers (assuming the number of producers equals the number of consumers).

Starter Template (Producer_Consumer.c):

#include<stdio.h>
#include<pthread.h>
#include<stdlib.h>
 
#define Buffer_Limit 10
 
int Buffer_Index_Value = 0;
char *Buffer_Queue;
 
void *Consumer(void *arg)
{
    while(1)
    {
        // TODO: Implement synchronization
        printf("Consumer:%d\t", Buffer_Index_Value--);        
    }    
}
 
void *Producer(void *arg)
{    
    while(1)
    { 
        // TODO: Implement synchronization
        Buffer_Queue[Buffer_Index_Value++] = '@';
        printf("Producer:%d\t", Buffer_Index_Value);
    }    
}
 
int main()
{    
    pthread_t producer_thread_id, consumer_thread_id;
    Buffer_Queue = (char *) malloc(sizeof(char) * Buffer_Limit);            
    pthread_create(&producer_thread_id, NULL, Producer, NULL);
    pthread_create(&consumer_thread_id, NULL, Consumer, NULL);
    pthread_join(producer_thread_id, NULL);
    pthread_join(consumer_thread_id, NULL);
    return 0;
}
